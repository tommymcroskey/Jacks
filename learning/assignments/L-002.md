## Bounded contract for peer review

Proposed signature: `DepositResult apply_deposit(const DepositState& current,
const Deposit& deposit)`. These are ordinary C++17 aggregates and a tagged result;
no overloaded arithmetic, symbol tables, event-kind framework, or new dependencies.

| Type | Fields |
| --- | --- |
| `DepositState` | `cash_minor_units`, `quantity_units`, optional `mark_minor_units`, `net_deposits_minor_units`, `last_sequence` |
| `Deposit` | `amount_minor_units`, `sequence` |
| `DepositApplied` | `state` (new `DepositState`), `equity` (existing `Equity`) |
| `DepositError` | `invalid_state`, `invalid_amount`, `invalid_sequence`, `overflow` |
| `DepositResult` | `std::variant<DepositApplied, DepositError>` |

Numeric fields are signed 64-bit integers; optional mark follows L-001. Money is
in minor currency units (100 per fictional CU), quantities are whole asset units.

**Initialization:** engineering/caller validates the opening snapshot using
`calculate_equity`, records opening equity externally, and sets net deposits and
last sequence to zero. The transition does not reconstruct history. For supplied
current states, structural validity means nonnegative cash, quantity, present
mark, net deposits and last sequence, plus representable available current equity.
It does not independently prove that the supplied flow counter/history is genuine.
Missing mark with zero holdings is valid; positive holdings require a mark.

**Error precedence and outcome:**

1. Invalid current state, including any failed current valuation: `invalid_state`.
2. Deposit amount not strictly positive: `invalid_amount`.
3. Sequence not positive or not greater than last accepted: `invalid_sequence`.
   Gaps are allowed; zero is only the initialization sentinel. No ID registry.
4. Unrepresentable cash or net-deposit update: `overflow`, checked before arithmetic.
5. Unrepresentable candidate equity from `calculate_equity`: `overflow`.

Success increases cash and net deposits by the amount, records the sequence, and
returns new state plus L-001's equity. Quantity and mark stay fixed. With valid
current state and unchanged quantity/mark, candidate missing/invalid-mark errors
should not arise; any such unexpected L-001 error rejects as `invalid_state`.
Input state is never mutated on success or failure. Rejected events return no
candidate state and consume no sequence; the caller retains the prior state.

Rejecting candidate valuation overflow is deliberate for this small operation.
It supersedes ENG-003's unaccepted accept-with-valuation-error proposal here.
Withdrawals, trades, fees, mark updates, batches, parsing, profit/return APIs,
storage and the general backtester are outside L-002.
