# L-003: separate funding from investment profit

Owner: Tommy. Mentor/interface/build owner: engineering. Reviewers: engineering

## Purpose

The company is building ordered deposit replay and automatic build/test checks.
Engineering owns that infrastructure; research supplies independent executable
accounting examples and risk challenges rejection and boundary behavior.
Those deliverables can run using your accepted valuation and deposit functions.

Your contribution is one pure calculation for the eventual replay summary:

`profit = current equity - opening equity - deposits during the interval`

Equity is the account's value. A deposit increases that value through owner
funding; it is not investment profit. The opening equity stays fixed for the
interval. Profit is signed: a negative result means a loss after accounting for
funding. This is an amount in minor currency units, not a percentage return.

## Exact interface and behavior

The declaration is in `include/jacks/profit.hpp`:

```cpp
ProfitResult calculate_profit(
    Equity opening_equity,
    Equity current_equity,
    std::int64_t net_deposits_minor_units);
```

`Profit` contains signed `int64_t minor_units`. `ProfitResult` contains either
`Profit` or `ProfitError` (`invalid_input`, `overflow`). The function returns a
tagged domain error, not an exception for bad input.

1. Each input value must be nonnegative. Any negative input returns
   `invalid_input`, before representability checks.
2. Return the exact mathematical result when it fits `int64_t`, including zero,
   negative values, and both representable endpoints.
3. Otherwise return `overflow`. Never perform overflowing signed arithmetic;
   do not reject a representable result merely because a chosen intermediate
   expression would overflow.

This function verifies arithmetic, not whether the supplied values describe a
real deposit-only history. Valid supplied inputs can produce positive or negative
profit. Actual deposit-only replay with fixed holdings/mark should produce zero.
There is no state mutation, valuation call, event processing, withdrawal support,
floating-point calculation, percentage-return calculation, or history validation.

The deposit argument means funding **during this interval**. The new-run replay
starts its counter at zero, so its final counter is the interval's funding.
Opening cash is already part of opening equity and must not be counted again.
