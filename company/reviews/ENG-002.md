**Interface — opening state (must agree before implementation).** Accept a
configurable, validated opening snapshot. Research's 100 CU opening capital is
outside that interval's flows. Risk's zero-cash opening is a fixture using the
same interface, followed by an explicit deposit. Record opening equity once and
initialize interval flows to zero. Profit is ending equity minus opening equity
minus interval net flows. Never count opening cash again as an interval deposit.
For the first fixtures use zero opening holdings. A nonzero opening holding
requires an available opening mark before interval profit can be reported.

**Interface — sequence and duplicate identity (must agree).** Use one positive,
strictly increasing sequence number as both event ID and availability order
within a ledger run. Gaps are allowed. Compare with the last accepted sequence;
duplicates and backward events fail without changing balances or that sequence.
This removes a second ID set without weakening duplicate detection under this
contract. It does not detect the same business event relabeled with a new number;
source deduplication is deferred. Fixture timestamps, if present, must not go
backward and use sequence to break ties. No separate execution/arrival clock or
out-of-order ingestion is proposed. Prices become observable only at their mark
event; a later mark cannot change an earlier snapshot.

**Interface — typed values versus parsing (must agree).** Core input consists of
integer money, integer whole units, and explicit event variants. Core checks
negative balances, event magnitudes, prices, fees, insufficient cash, overselling,
ordering, and overflow. Reject zero/negative deposit and withdrawal magnitudes.
Trade prices must be positive. Proposed valuation marks may be zero (a worthless
asset still has a value) but never negative; absent is different from zero.
Text syntax, nonnumeric strings, currency conversion, and external asset symbols
belong to a future input adapter. First fixtures have one implicit currency and
asset, so no parser or symbol registry is needed. Risk's malformed-number and
unsupported-symbol checks remain required when such an adapter exists, not as
unused core machinery now. Typed input does not remove range/semantic validation.

**Maintainability — scope stays small.** One state transition and one pure
valuation function suffice. A pure function reads inputs and returns a result
without changing the ledger. Risk's optional balance-update apprentice idea
overlaps event validation; reserve valuation as the single contribution instead.
Rejection must preserve all accepted state. Document and test overflow prevention;
overflowing signed C++ arithmetic has undefined behavior. Defer fractional units, return
percentages, corporate actions, and ingestion infrastructure.

**Preference — nonblocking.** File/type names can change during interface review;
C++17 and CMake are engineering defaults, not business requirements.
